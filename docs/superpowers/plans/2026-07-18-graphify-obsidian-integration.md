# Graphify and Obsidian Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local, continuously refreshed WCORE code graph, expose every generated node in Obsidian, and turn the vault into a query-first memory that reduces repeated code reads, tokens, and navigation time.

**Architecture:** Install Graphify 0.9.18 in an isolated uv tool environment. A PowerShell wrapper stages Web API code and a `.gs`-to-`.js` GSheet mirror into one prefixed corpus, serializes updates with a Windows mutex, validates the graph, and exports generated notes into a dedicated vault namespace. Native MOCs and reciprocal plan/spec links provide the human-memory layer; project OpenCode instructions enforce Graphify first, Obsidian second, raw code third.

**Tech Stack:** Graphify 0.9.18, uv, PowerShell 5.1, Windows Task Scheduler, OpenCode project plugins/skills, Obsidian Markdown/MCP, Git.

- [ ] **Step 3: Implement staging functions**

The script must expose these functions when dot-sourced:

```powershell
Sync-WebCorpus -SourceRoot $SourceRoot -DestinationRoot $DestinationRoot
Sync-GSheetCorpus -SourceRoot $SourceRoot -DestinationRoot $DestinationRoot
New-StagingTree -RepositoryRoot $RepositoryRoot
```

Implementation rules:

- default production staging to `K:\WCORE\.tmp\graphify-input` while retaining `-StagingRoot` parameterization for fixtures;
- build into the sibling `K:\WCORE\.tmp\graphify-input.next`;
- write `.wcore-graphify-staging` with exact ownership content in every staging root;
- use exact ownership-marked siblings `<StagingRoot>.next` and `<StagingRoot>.previous`;
- before moving or recursively deleting final, `.next`, or `.previous` trees, require the exact expected path and ownership marker; abort without deletion otherwise;
- before building, restore owned `.previous` when final is missing, or delete owned `.previous` when an owned final already exists;
- replace by renaming final to `.previous`, renaming `.next` to final, then deleting owned `.previous`; immediately restore `.previous` if the second rename fails and preserve it if restoration fails;
- validate completed `.next` before moving final, run the pre-swap seam, revalidate before any final move, and validate once more immediately before renaming `.next` to final; preserve an invalid `.next` and the unmoved prior corpus;
- reject reparse points in every existing path component from repository root through source and staging roots, and during component-by-component source traversal; abort when physical ancestry inside the repository cannot be proven;
- use fail-closed `git ls-files -z -- <pathspec>` discovery with redirected output bytes, strict UTF-8 decoding, and NUL parsing; a nonzero exit, stderr failure, malformed output, empty result, missing file, or path outside the source root aborts staging;
- allow recursive filesystem discovery only through the explicit fixture test switch outside Git;
- preserve `web-api/` and `gsheet/` path prefixes;
- Web allowlist: `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.json` from tracked source/manifests;
- Web exclusions: `node_modules`, `dist`, logs, `.env*`, databases, caches, Docker files, generated output;
- GSheet input: canonical `.gs` plus `appsscript.json`;
- convert each `.gs` destination extension to `.js` without altering content;
- skip a `.js` file when a same-stem `.gs` exists;
- atomically replace the prior staging directory after successful copy;
- return a structured object with Web count, GSheet count, and total bytes.
