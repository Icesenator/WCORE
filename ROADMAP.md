## Roadmap canonique normalisee (2026-09-13)

> Section de pilotage etablie le 2026-09-13 (jalon R-012, superviseur). Elle inventorie tout le travail ouvert du projet (monorepo Web/GSheet + workstream CM X), avec un identifiant stable `WC-##`, un etat parmi `TODO`, `IN_PROGRESS`, `BLOCKED`, `DONE` et une source. Les sections detaillees ci-dessous restent la reference d'implementation et conservent les elements termines avec preuve (cases cochees, dates, commits, deploiements). Cette section ne supprime aucune information : elle normalise les statuts et signale explicitement les deduplications.

### Regles de pilotage

- Une seule **tache d'execution** principale a la fois (slot d'execution concret). **`WC-01` CM = WORKSTREAM PRINCIPAL permanent** de cet agent (`WC01_PRIMARY_WORKSTREAM=TRUE` ; `CM_IS_NOT_A_WATCHER_ONLY=TRUE` ; `T0_ALREADY_CONSUMED=TRUE` : T0 = 2026-09-14 10:50:29 Europe/Paris **traite** — checkpoint officiel C2 fait, synthesis 9/9 PASS, D publiee). La sémantique watcher/time-gate pré-R-024 (WC-01 armé jusqu'à T0, hors slot) est **HISTORIQUE** (conservée pour audit, non CURRENT). Règle générale maintenue : un watcher/time-gate est du travail durable **suivi** qui n'occupe **pas** le slot et n'immobilise pas la file (`TIME_GATED_TASK_DOES_NOT_BLOCK_OTHER_WORK=true` ; pas de churn de statut pour un watcher, R-023).
- **Convention d'ID immuable** : les taches historiques gardent `WC-##`. Toute NOUVELLE tache/politique utilise un `PRIORITY_ID` stable `P<0-3>-<DOMAINE>-<NOM>` (`P0-SEC-*`, `P0-PROD-*`, `P0-DATA-*`, `P1-REL-*`, `P1-GOV-*`, `P1-OBS-*`, `P1-DATA-*`, `P2-CHAIN-*`, `P2-CM-*`, `P2-MAINT-*`, `P3-DOC-*`, `P3-OPT-*`). Jamais recycle, jamais renomme (`-RETRY`/`-FINAL`/`-2`/nouvel ID apres reboot interdits) : meme tache = meme ID jusqu'a `DONE`.
- Une tache passe en `DONE` uniquement avec une preuve reproductible citee dans la section detaillee (test, commit, deploiement ou verification datee).
- Une tache passe en `BLOCKED` uniquement avec une cause demontree et une condition de reprise (ex. `P2-CHAIN-ZERO-RPC` : endpoint provider externe requis). Une incertitude de statut reste `TODO` et n'est pas falsifiee en `BLOCKED`.
- Les invariants permanents des phases terminees (parite FX, metadata/CI du package genere, pricing FX, validation du schema, gestion des sunsets) ne sont pas des taches : ils vivent dans les sections detaillees. Les deadlines futures documentees (Mint withdrawal gateway 2026-10-20, Cronos zkEVM 2027-06-03) sont de la veille, pas des taches ouvertes.
- Les vues detaillees `wcore-web/ROADMAP.md` et `wcore-gsheet/ROADMAP.md` restent des sources par runtime, non concurrentes. En cas de divergence, cette section fait statut ; les vues restent la source d'implementation.
